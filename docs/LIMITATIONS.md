# Known limits

- Tested target: Windows 11 x64, OBS 33.0.0 / WebSocket 5.7.6, one microphone capture source. Other installed versions need their own checks.
- OBS 33 removed old Monitor Only output behavior. Legacy repair is guarded, not the demonstrated OBS 33 path.
- Local state/meters/tracks do not prove delivered Twitch audio. No complete routing inference, driver diagnosis, echo classification, HLS monitoring, game-audio repair, or AI diagnosis is claimed.
- Replies are public/copyable. Accounts do not prove independent humans. An owner's offline-channel check proves transport and matching, not audience playback.
- No outside-creator study or measured benefit over manual controls/simple alerts is complete. Do not invent timings, retention, adoption, or winning odds.
- OBS setters are not atomic compare-and-set. Concurrent external control remains a race risk; unknown outcomes need reconciliation.
- Unexpected Twitch gaps lose messages. Start a new check after reconnect.
- Firewall containment was checked by exact rule readback, not a second-host penetration/reachability test. OBS's listener itself is not loopback-only.
- The app is unsigned, with no paid certificate or hosted updater. Reputation prompts vary by Windows policy.
- Windows Application Control blocked the final rebuilt standalone executable on the development PC. An earlier package completed the rehearsal; that does not establish final-package launch success. The source-build workflow is supplied separately. No policy bypass is part of the setup.
- Shared-client scale, API quota behavior across many installations, independent moderation operators, real-account revocation, and older-OBS monitoring repair are not claimed as field tests.
- Codex built the app; runtime AI does not process private audio/chat. Prior audio-monitoring tools exist. The bounded contribution is this integrated recovery workflow.
